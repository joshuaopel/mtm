# Making tracks

End-to-end: an empty Blender scene to something you can drive.

## The one idea to get straight first

**A track file is a recipe, not geometry.**

There is no road mesh and no terrain mesh in your `.blend` unless you choose to
make one. The game builds the road ribbon along your spline at load time, and
generates the ground underneath it. What you export is a few kilobytes of JSON
saying *where the road goes* and *what shape the land is*.

So the question "how do I model the track?" doesn't quite apply. The order is:

1. Draw a **road curve**.
2. Decide what the ground does — either place a few empties and let the game
   generate it, or sculpt a mesh yourself.
3. Press **Build Course Preview** to see the result as real geometry.
4. Export.

The road carves the terrain, not the other way round. You never align a spline
onto a landscape; you draw the line and the land gets out of its way.

## Five minutes to a driveable track

1. Install the add-on (see [`blender/README.md`](../blender/README.md)) and
   open the **MTM** tab in the 3D viewport sidebar (<kbd>N</kbd>).
2. **New Track Scaffold**. You get an oval road curve, a terrain bounds box, a
   sun, and a preview of the ground you'd be driving on.
3. Tab into Edit Mode on `MTM_Road` and drag points around. Press **Build
   Course Preview** again to see what you did.
4. Set **Track ID** and **Name** in the Track panel.
5. Set the **Export Path** to your `public/content/` folder, ending in
   `something.mtmtrack.json`.
6. **Export Track**.

With `npm run dev` running it appears in the level select immediately. No
manifest to edit.

That is a complete track. Everything below is about making it good.

## Shaping the road

The curve is the single most important object in the scene: it is the racing
line, the road surface, the AI path, and the thing the terrain is carved
around.

- **Only the shape matters.** The exporter samples the curve into points and
  the game re-splines them with centripetal Catmull-Rom. Curve type, handles
  and tilt are yours to work however you like.
- **Elevation is part of the shape.** Move points up and down; the road follows
  and the terrain comes with it. This is how you get climbs and drops.
- **Jumps need tightly-spaced points.** A table-top is a short run of points at
  a raised height with a sharp return. Widely-spaced points can only ever make
  rolling hills, because the re-spline smooths everything in between.
- **Point Spacing** (Road panel) controls how finely the curve is sampled at
  export. Tighter follows a complex curve more faithfully and makes a bigger
  file.
- **Road Width** and **Shoulder** set the flattened corridor. The shoulder is
  the blend from road level back to the landscape, so a wide shoulder gives
  forgiving run-off and a narrow one gives you a ledge.

## Ground, option 1: generated

The default. The game builds the terrain from noise plus features you place, so
there is nothing to model and the track file stays tiny.

Shape it by adding Empties and tagging them **Terrain Feature**. Each one is a
hill, crater, plateau or ridge; its radius comes from its X scale, so you size
it by scaling it in the viewport. Set **Amplitude**, **Frequency** and **Seed**
in the Terrain box for the background roughness.

Press **Build Course Preview** after every change. The preview is generated by
a Python port of the game's own code — over a 760m course the two agree on
every height to within three micrometres — so it is not an impression of the
terrain, it is the terrain.

## Ground, option 2: sculpted

When you want to model the landscape by hand.

1. Switch **Terrain Source** to **Sculpted Mesh**.
2. **New Sculpted Terrain** builds a grid sized to your course, tags it, and
   adds the road carve modifier.
3. Sculpt it — proportional edit, the sculpt tools, modifiers, whatever you
   like. It is an ordinary mesh.
4. Export. The mesh is sampled onto the game's height grid and written into the
   track file.

Two constraints worth knowing before you spend an evening on it:

- **It bakes to a heightfield.** Overhangs, caves and vertical cliff faces
  cannot be represented — each bakes to its topmost surface and the truck
  drives over the top. This is not an exporter limitation to route around; the
  physics ground is a heightfield because that is what the wheels ray-cast
  against.
- **It costs file size.** 128 segments is about 86KB of base64, 256 about
  340KB. **Bake Resolution** trades detail against size.

### The live road carve

This is the part that makes sculpting workable. **Add / Update Road Carve** puts
a Geometry Nodes modifier on the terrain that flattens the ground under the
road curve, blending back out across the shoulder — and it re-evaluates as you
drag the spline. Move the road, the trench moves with it; move it away, the old
line springs back to the sculpt.

It is a modifier, not an edit. Your sculpt stays in the base mesh, so the carve
can be retuned or removed without having lost anything. The exporter bakes the
*evaluated* mesh, so what the modifier shows is what ships.

Re-run **Add / Update Road Carve** after changing Road Width or Shoulder — the
modifier keeps its own copy of those numbers.

**Carve Road Into Terrain** (in the Terrain box) is a second, independent carve
the game does at load time. Leave it on: it guarantees the physics ground and
the road agree exactly, even if the modifier was removed or the sculpt drifted.
Turn it off only if you have modelled the road bed yourself at exactly the
spline's elevation — otherwise the trucks spawn inside a hill and start the race
on their roofs.

## Ground textures

The terrain blends up to four tiled textures. There are two ways to drive that
blend, and they combine.

### Automatic (the default)

Leave **Ground Texture** on **Automatic** and the game picks layers from the
Surface theme: your surface as the base, rock blended onto anything steep, and
for the softer surfaces a worn verge either side of the racing line. Nothing to
set up, and no paint data in the file.

The slope ramp runs from 32° to 52°. Those numbers were measured rather than
guessed — a ramp starting at 20° turned nearly half of the built-in courses to
rock, because rolling terrain spends a lot of its area between 20° and 40°.

### Choosing your own layers

Switch to **Choose Layers** and name four textures. Each is either a built-in
surface (`dirt`, `sand`, `snow`, `mud`, `slag`, `grass`, `rock`) or a path to an
image in `public/content/`. **Tile** is metres per repeat.

A blank slot ends the list — the channels are positional, so layer 3 cannot
exist without layer 2.

**Automatic Blending** gives you the two rules the defaults use, with the
numbers exposed: layer 1 on steep ground, layer 2 along the road.

### Painting

For everything the rules can't express — a scorched patch, a dry riverbed, a
gravel run-off — paint it.

1. **Paint Terrain** creates the paint attribute and drops you into Vertex
   Paint mode.
2. The **Base / Layer 1 / Layer 2 / Layer 3** buttons set the brush to the
   colour that selects that layer: black, red, green, blue.
3. Paint. Red where you want layer 1, and so on. Black erases back to the base.

That is the whole interface — no UV unwrap, no image file to manage, and the
paint travels in the `.blend`. At export it is baked onto the same grid as the
heights.

Painting needs a sculpted terrain (there is no mesh to paint on otherwise), and
it wins over the rules wherever you painted: someone who painted a hillside
meant it.

## Populating the course

- **Build Start Grid** — a staggered grid behind the line. Optional; without it
  the game generates one.
- **Place Checkpoints** — hand-placed gates. Optional; without them the game
  puts gates around the road.
- **Auto Barriers** on (default) has the game fence the course at load time —
  cheap, and the file stays small. **Generate Barrier Walls** bakes them as real
  objects you can then edit, and turns auto-barriers off so it isn't fenced
  twice.
- **Scatter Props** dresses the roadside. **Drop To Terrain** settles anything
  selected onto the ground.
- Model your own geometry, tag it **Scenery Mesh**, and give it a collider.

### Props

Tag an Empty **Prop** and pick a **Kind**. Most are scenery — trees (conifer,
palm, bare), rocks, barrels, cones, crates, signs, towers, gantries — and tick
**Solid** if you want them to stop a truck.

Four kinds take a **Size** in metres rather than a scale, because their
proportions are the thing you are actually authoring:

| Kind | Size means | Notes |
| --- | --- | --- |
| **Stunt Ramp** | width, height, length | A kicker. Always solid. |
| **Table-Top** | width, height, length | Up-ramp, flat deck, down-ramp. Always solid. |
| **Billboard** | panel width, panel height, post height | Takes an **Image**. |
| **Flag** | cloth width, cloth height, mast height | Takes an **Image**. Waves. |

Ramps and table-tops are the only props with real collision geometry rather
than a box — they are convex hulls built from the same description as the
visible mesh, so what you see is what the wheels ride on. They kick towards
their local **-Y in Blender**, so point the Empty down the road.

Defaults are a 8 x 2.5 x 11m kicker (about 13 degrees) and a 11 x 3 x 26m
table-top. Steeper is not automatically better: past about 20 degrees a truck
stops climbing and starts hitting.

**Billboards** and **flags** take an image path relative to `public/content/`.
Drop a PNG in there, type its name, and it appears on the hoarding. Leave it
blank for a plain coloured panel.

### Collision has to be convex

The physics engine resolves boxes and convex hulls properly but not concave
triangle meshes, which silently let trucks through at speed. **Collider From
Selection** makes a box or a convex hull; **Check Colliders** tells you, in
metres, how far from convex a shape is. Split a concave shape into convex pieces
and give each its own collider. The exporter refuses to write one that would
fail.

## Exporting

**Validate Track** first — it catches the things that produce a technically
valid file that plays badly. Then **Export Track**, which writes the JSON and,
if you have any scenery, a matching `.glb` beside it.

Copy both into `public/content/`. Files named `*.mtmtrack.json` are discovered
automatically. A custom file whose `id` matches a built-in replaces it, so you
can iterate on a stock course without renaming anything.

With the dev server running, saving over a track reloads it immediately —
including the race you are currently driving.

## When something looks wrong

| Symptom | Cause |
| --- | --- |
| "No object has the 'Road Spline' role" | Nothing is tagged as the road. Select the curve, **Tag Selected → Road Spline**. |
| "...is marked as the road but is not a curve" | The role is on a mesh. The road has to be a curve. |
| "Road resampled to fewer than 3 points" | **Point Spacing** is larger than your course. Lower it. |
| Preview is flat | **Amplitude** is zero, or the feature empties aren't tagged. |
| Road sits in a trench | Sculpted ground far above the road with a narrow shoulder. Sculpt closer to the road's elevation, or widen the shoulder. The exporter warns about this. |
| Trucks start on their roofs | **Carve Road Into Terrain** is off and the sculpt doesn't contain the road bed. Turn it back on. |
| Terrain is a 100m square in a huge course | Fixed — but if you see it, the Terrain-role object isn't covering the course. |
| Painting does nothing | **Ground Texture** is on Automatic, or Terrain Source is Generated. |
